# 名詞定義（Glossary）

本文件整理專案中會用到的名詞與基本概念。

> 標示「待規格確認」的內容，會在閱讀 VESA 官方規格後更新。

---

## 1. 協定與標準

| 縮寫 | 全名 | 說明 |
|---|---|---|
| **DDC/CI** | Display Data Channel / Command Interface | 電腦與螢幕之間**下指令、收回覆**的規則。DDC 是通道，CI 是在通道上對話的方式。由 VESA 制定 |
| **MCCS** | Monitor Control Command Set | 規定**每個螢幕設定的編號與意義**（例如哪個編號代表亮度）及數值範圍。相當於 DDC/CI 對話時使用的「字典」。由 VESA 制定 |
| **EDID** | Extended Display Identification Data | 螢幕的**電子名片**，包含廠牌、型號、支援的解析度。螢幕接上電腦時，電腦會自動讀取 |
| **I2C**（I²C） | Inter-Integrated Circuit | 晶片之間用**兩條線**溝通的方式，由 Philips（現 NXP）發明。DDC/CI 建立在 I2C 之上 |
| **USB** | Universal Serial Bus | 本專案用來連接筆電與 Pico |
| **HDMI** | High-Definition Multimedia Interface | 筆電與螢幕之間的連接線 |
| **VESA** | Video Electronics Standards Association | 制定 DDC/CI、MCCS 等顯示相關標準的組織 |

### 其他常見硬體通訊協定

| 協定 | 線數 | 特性 | 常見用途 |
|---|---|---|---|
| **I2C** | 2 條 | 慢；一組線可掛多個裝置，以位址區分 | 感測器、螢幕的 DDC/CI、電源管理晶片 |
| **SPI**（Serial Peripheral Interface） | 4 條以上 | 快；每增加一個裝置需多一條選擇線 | 記憶體、SD 卡、小型顯示面板 |
| **UART**（Universal Asynchronous Receiver-Transmitter） | 2 條 | 通常一對一 | 除錯輸出、模組間簡單通訊 |

## 2. I2C 相關

| 名詞 | 全名 | 說明 |
|---|---|---|
| **SDA** | Serial Data | I2C 的資料線，0 與 1 依序在這條線上傳送 |
| **SCL** | Serial Clock | I2C 的時脈線，提供節拍，告訴接收方何時讀取 SDA 上的值 |
| **匯流排**（bus） | — | 多個裝置**共用的一組線**，類似公車路線，沿途各站都能上下車 |
| **主控方**（master） | — | 發起通訊的一方。本專案中為電腦 |
| **位址**（address） | — | I2C 上每個裝置的「門牌號碼」，只有被呼叫的裝置會回應 |

### I2C 運作方式

- 由**主控方**發起通訊，其他裝置依**位址**決定是否回應
- 所有裝置共用 SDA、SCL 兩條線
- 比喻：一人用 SCL **打拍子**，另一人在每個拍子上用 SDA **舉牌**（朝上為 1、朝下為 0），接收方隨拍子逐一讀取

### 螢幕在 I2C 上的位址

| 位址 | 用途 |
|---|---|
| `0x50` | EDID（讀取螢幕電子名片） |
| `0x37` | DDC/CI（與螢幕對話） |

## 3. 螢幕相關

| 名詞 | 全名 | 說明 |
|---|---|---|
| **OSD** | On-Screen Display | 按下螢幕實體按鍵或搖桿時**跳出的設定選單** |
| **VCP** | Virtual Control Panel | 把 OSD 上的各項設定**編上號碼**，讓電腦能透過號碼讀寫。相當於 OSD 的「遙控器版本」 |
| **VCP code** | — | 某一項設定的編號（例如亮度對應的編號）。確切編號以 MCCS 規格與實測結果為準（待規格確認） |
| **Capabilities string** | — | 螢幕回報「我支援哪些 VCP code」的文字字串，格式由規格定義 |

### VCP 數值類型

| 類型 | 說明 | 例子 |
|---|---|---|
| **連續型**（continuous） | 介於 0 到最大值之間的數值 | 亮度、對比 |
| **非連續型**（non-continuous） | 從固定選項中選擇一個 | 輸入源、色彩模式 |

## 4. DDC/CI 運作原理

### 從「讀名片」到「對話」

1. **DDC**：最初用途是讓電腦讀取螢幕的 EDID，以自動設定解析度
2. **DDC/CI**：將單向讀取擴充為**雙向對話**，電腦可下指令給螢幕（例如調整亮度）

### 通訊路徑

HDMI 線內除了傳送**影像**的高速資料線之外，另有兩條 **DDC 線**（SDA、SCL），構成一條 I2C 匯流排，專門傳送控制訊息。

```
HDMI 線
 ├─ 影像資料線（高速，傳送畫面）    ← 與本專案無關
 └─ DDC 線（SDA + SCL）           ← I2C 匯流排，傳送控制訊息
```

### 一次對話的流程

1. 電腦（主控方）將指令寫入位址 `0x37`
2. 螢幕內的控制晶片處理指令
3. 電腦再從位址 `0x37` 讀取回覆

## 5. 協定分層

本專案涉及的協定是**多層疊加**的，每層負責不同的事：

```
MCCS      →  內容的「字典」：每個編號代表什麼設定、數值範圍
DDC/CI    →  信封格式與郵寄規則：訊息如何組成、如何檢查錯誤、等待多久
I2C       →  道路：電訊號如何在兩條線上傳送 0 與 1
HDMI 線   →  實體連接
```

### 規格文件中可以找到的內容（待規格確認）

| 規格 | 預期內容 |
|---|---|
| **DDC/CI** | 訊息由哪些 byte 組成、裝置位址、長度表示方式、checksum 計算方式、指令類型（讀取 VCP、設定 VCP、要求能力清單等）、訊息之間的等待時間、錯誤處理方式 |
| **MCCS** | 各 VCP code 的意義與數值範圍、capabilities string 格式 |

## 6. 介面（Interface）與協定（Protocol）的區別

兩者都是「規定」，但層次完全不同：

| | 介面（Interface） | 協定（Protocol） |
|---|---|---|
| 制定者 | **本專案自行設計**（程式架構） | **外部組織**（例如 VESA） |
| 規範對象 | 程式內部的各個元件 | **兩台不同的裝置**（電腦與螢幕） |
| 可否修改 | 可以，依設計需求調整 | 不行，修改後裝置之間無法溝通 |
| 例子 | `IMonitor`、`ITransport` | DDC/CI、MCCS、I2C、USB |

### 本專案的介面

| 介面 | 說明 | 實作 |
|---|---|---|
| **`IMonitor`** | 統一的「讀寫 VCP」函式，讓上層不需知道背後是哪種裝置 | `WindowsApiMonitor`、`DdcCiMonitor` |
| **`ITransport`** | 統一的「送出 bytes、接收 bytes」函式，讓協定層不需知道傳輸方式 | `SerialTransport`、`MockTransport` |

> 名稱開頭的 `I` 代表 Interface，是 Windows 與 C# 常見的命名慣例。在 C++ 中，介面是「只宣告函式、不提供實作」的類別。

### 元件之間的兩種關係

| 關係 | 意思 | 例子 |
|---|---|---|
| **呼叫**（uses） | A 需要 B 幫忙完成工作 | CLI 呼叫 `IMonitor`；`DdcCiMonitor` 呼叫 `ITransport` |
| **實作**（implements） | A 承諾提供 B 規定的函式 | `DdcCiMonitor` 實作 `IMonitor`；`SerialTransport` 實作 `ITransport` |

## 7. 開發與測試相關

| 名詞 | 說明 |
|---|---|
| **Mock** | 非縮寫，英文意為「模仿的、假的」。測試中使用的**替身元件**，依預先寫好的劇本回應，並記錄收到的內容，使測試不需真實硬體 |
| **依賴注入**（Dependency Injection） | 元件不自行建立所依賴的對象，而是由外部傳入。例如 `DdcCiMonitor` 接收一個 `ITransport`，因此可傳入真實的 `SerialTransport` 或測試用的 `MockTransport`，而不需修改程式碼 |
| **Spike** | 正式開發前，用小型程式驗證技術可行性。本專案的探測程式（probe）即屬此類 |
| **Checksum** | 檢查碼。依資料內容計算出的值，接收方重新計算並比對，用以發現傳輸中的錯誤。計算方式依協定規定（待規格確認） |
| **Framing**（分框） | 在連續的位元組串流中標示「一則訊息從哪裡開始、到哪裡結束」的方法。I2C 由硬體訊號標示邊界；USB serial 沒有訊息邊界，需自行定義 |
| **Handle** | 作業系統提供的「識別代號」，代表一個已開啟的資源（例如一台螢幕）。使用完畢必須歸還，否則會造成資源洩漏 |
| **Firmware**（韌體） | 直接在硬體上執行、控制硬體行為的程式 |

## 8. 硬體相關

| 名詞 | 說明 |
|---|---|
| **Pico** | 全名 **Raspberry Pi Pico**，Raspberry Pi 公司推出的**微控制器開發板**。與 Raspberry Pi 電腦不同，它**沒有作業系統**，開機後直接執行燒錄進去的單一程式。本專案用它模擬一台螢幕 |
| **微控制器**（Microcontroller, MCU） | 將處理器、記憶體與輸入輸出功能整合在一顆晶片上的小型電腦，常用於嵌入式裝置 |
